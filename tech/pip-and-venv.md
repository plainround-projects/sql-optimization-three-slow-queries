# pip, virtual environments and lock files

## What it is

**pip** is Python's package installer. It downloads packages from the **Python Package Index (PyPI)**, a public website of Python packages, and installs them. A **virtual environment** ("venv") is a private folder holding its own copy of the Python tools and its own installed packages, so one project's packages never clash with another's. A **lock file** is a list of every package, down to the exact version, that a project needs, so every machine installs the same thing.

## Why this repository uses it

The checks in this repository (ruff, mypy, pytest...) are only worth something if they run the same tools on every machine. The Makefile therefore creates a virtual environment and installs *exactly* the locked versions with hash checking.

## Where it appears

| File | What it does |

## How it works underneath

**Why a venv.** The Python that came with your computer should not be changed by project work. `python -m venv .venv` creates a folder `.venv` containing: `bin/` (programs: `python`, `pip`, and later the commands of installed packages), `lib/python3.x/site-packages/` (installed packages) and `pyvenv.cfg` (which Python it was made from). You do not need to "activate" it if you call the programs by their path, as the Makefile does: `.venv/bin/pip`, `.venv/bin/python`.

**Installing.** `pip install name` looks the name up on PyPI, picks a version that fits the rules, downloads a **wheel** (or builds from source if there is none), also installs the packages it depends on, and unpacks everything into `site-packages`.

**Version rules.** In `pyproject.toml` a package is described with a *range* (`>=3.2,<4`). Ranges are flexible but mean that two machines on different days can get different versions. A lock file pins exact versions (`==3.3.6`).

**Hashes.** Each downloadable file of a package has a **hash**: a fingerprint (here SHA-256, a 64-character hexadecimal number) computed from its bytes. If even one byte changes, the hash changes. A lock with `--hash=sha256:...` lines lets pip check that what it downloaded is exactly what was recorded, which defends against a tampered or swapped package.

**Flags used by this repository.**

- `-r file` reads requirements from a file, one per line.
- `--require-hashes` makes pip refuse to install unless *every* requirement is pinned with `==` and has hashes, and it checks them. It also turns off dependency lookups, because the lock already lists everything.
- `--no-deps` installs only the named thing, not its dependencies.
- `-e .` installs the project in the current folder in *editable* mode.
- `-q` quiet output.
- `--no-cache-dir` (as the environment variable `PIP_NO_CACHE_DIR=1`) do not keep downloads.

**Markers in lock files.** A line such as `psycopg-binary==3.3.6 ; implementation_name != 'pypy'` means "install this only when the condition is true". The condition is written in a small language of environment markers (operating system, Python version, Python implementation). A **universal** lock holds the packages for all systems at once.

**Where the lock comes from.** It is generated, never typed by hand (see the uv note); the comment at the top says which command made it.

## Walkthrough of this repository's use

### Creating and filling the environment

`Makefile`, lines 22 to 26:

```make
$(STAMP): requirements-dev.lock pyproject.toml
	$(PYTHON) -m venv $(VENV)
	$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock
	$(VENV)/bin/pip install -q --no-deps -e .
	touch $@
```

1. `$(PYTHON) -m venv $(VENV)` creates `.venv` with Python 3.13 (or 3.12, whichever the Makefile found).
2. `.venv/bin/pip install -q --require-hashes -r requirements-dev.lock` installs everything in the dev lock. `--require-hashes` makes pip check every download against the recorded hashes and refuse any line that has none.
3. `.venv/bin/pip install -q --no-deps -e .` installs this project itself in editable mode. `--no-deps` is used because step 2 already installed all dependencies, and a second resolution could pick different versions.
4. `touch $@` marks the work as done.

### Reading a lock file

`requirements.lock`, lines 1 to 8:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock
psycopg==3.3.6 \
    --hash=sha256:a1db9f7148b06a28606767efaca51fa6f9398c5c0a3810519be69d7000bdb631 \
    --hash=sha256:c081f2250df751a943036e42db6df4571c66cd0aabe8291a7a506512b12007d2
    # via sql-optimization-three-slow-queries (pyproject.toml)
psycopg-binary==3.3.6 ; implementation_name != 'pypy' \
    --hash=sha256:05a83ac9fd52b9bca7cb5ab04b3691163170bd16f53defa27216ea3aa07ee781 \
```

Lines 1 and 2 are comments written by the tool that generated the file: it was made by **uv** with `uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock`. `--universal` makes the file valid on every operating system; `--python-version 3.12` targets the oldest supported Python. Line 3 is the first requirement: `psycopg==3.3.6`, exact version. The lines that follow, each starting with `--hash=sha256:`, are the allowed fingerprints: a package can have several files (for different systems), and any one of them may match. A backslash at the end of a line means the requirement continues on the next line. Line 6 is a comment, `# via sql-optimization-three-slow-queries (pyproject.toml)`: it says *why* this package is here (the project asked for it directly).

`requirements.lock`, lines 72 to 82:

```text
    --hash=sha256:fa34eb47969297471db7b7f193622c7e3ee839ec05abd05f1fe104d5b1b1dcf4 \
    --hash=sha256:fdccb3a0e184b03e9baa673b15a809cf36c339c85dbda0ebc25a698846dfbee8
    # via psycopg
typing-extensions==4.16.0 ; python_full_version < '3.13' \
    --hash=sha256:481caa481374e813c1b176ada14e97f1f67a4539ce9cfeb3f350d78d6370c2e8 \
    --hash=sha256:dc983d19a509c94dba722ee6abd33940f7c05a89e243c47e907eb4db6f1a43e5
    # via psycopg
tzdata==2026.5 ; sys_platform == 'win32' \
    --hash=sha256:8cc73c0a0bfca7dbfa59235d60b2eff82231dee33f53d206db1acd9173cfc0a7 \
    --hash=sha256:b683bd1b6659ddcd810ff02ad09ba821d4bf1065072805063eb35c49617905ac
    # via psycopg
```

Here are the other packages. `typing-extensions==4.16.0 ; python_full_version < '3.13'` is installed only on Python older than 3.13. `tzdata==2026.5 ; sys_platform == 'win32'` is installed only on Windows. Both carry `# via psycopg`: psycopg needs them. `psycopg-binary` (line 7) is `; implementation_name != 'pypy'`: skipped for the PyPy interpreter.

### In the Docker image

`Dockerfile`, lines 11 to 13:

```dockerfile
WORKDIR /app
COPY requirements.lock ./
RUN pip install --require-hashes -r requirements.lock
```

The same flag, `--require-hashes`, protects the image. Only the run-time lock is used there (four packages).

## Try it yourself

1. `.venv/bin/python --version` prints the Python of the venv (`Python 3.13.12` here).
2. `cat .venv/pyvenv.cfg` shows `include-system-site-packages = false` and the `command` that created the venv.
3. `.venv/bin/pip list` lists the installed packages with their versions; compare a few with `requirements-dev.lock` (for example `psycopg 3.3.6`, `ruff 0.17.3`).
4. `grep -c -- "--hash" requirements.lock` counts the hash lines of the run-time lock.
5. `.venv/bin/pip install --require-hashes --dry-run --force-reinstall psycopg==3.3.6` stops with `ERROR: Hashes are required in --require-hashes mode, but they are missing from some requirements.` and prints the hash the downloaded file actually had. Nothing is installed (`--dry-run`), and without hashes in the requirement pip refuses on principle.

## Mistakes people make

- Installing packages with the system Python (`sudo pip install`).
- Forgetting which venv is active and installing into the wrong one.
- Committing the `.venv` folder (it is large and machine-specific); `.gitignore` lists it.
- Editing a lock file by hand: the hashes then no longer match.
- Using `pip install -r requirements.txt` with loose ranges and expecting repeatable builds.
- Treating `--require-hashes` as optional: if one line is missing a hash, pip stops with a clear error, which is the point.

**How this repository avoids them.** It never uses the system Python for project work, always calls `.venv/bin/...` by path, keeps `.venv/` out of git, and generates the lock files from `pyproject.toml` instead of editing them. The same lock is used in the image.

## Check yourself

1. What does a virtual environment protect you from? *Packages of different projects (or the system) clashing with each other.*
2. What is a hash for? *To prove that a downloaded file is exactly the one that was recorded.*
3. What does `--no-deps` do? *Installs only the named package and skips its dependencies.*
4. What does the part after `;` on a lock line mean? *A condition (marker); the line applies only where the condition is true.*
5. Why call `.venv/bin/pip` instead of activating the venv? *The full path is unambiguous: the right pip is used no matter what the shell's `PATH` says.*
