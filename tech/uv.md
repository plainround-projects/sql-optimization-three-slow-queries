# uv

## What it is

**uv** is a very fast tool for managing Python packages, written in Rust. It can do the jobs of `pip`, `venv` and `pip-tools`. In this repository it is used for one job only: **compiling a lock file** from the dependency ranges in `pyproject.toml`. It is not needed to build, run or test the project.

## Why this repository uses it

The rule "pinned dependencies with hashes" needs a way to produce the pins. uv does it in seconds and records the command it was given.

## Where it appears

| File | Where uv shows |
|---|---|
| `requirements.lock`, lines 1 and 2 | The comment with the exact `uv pip compile` command. |
| `requirements-dev.lock`, lines 1 and 2 | The same, with `--extra dev`. |

## How it works underneath

`uv pip compile` reads the requirements (the `dependencies` and, with `--extra dev`, the `dev` group in `pyproject.toml`), asks PyPI which versions exist, and solves a puzzle: find one version of every package so that all the ranges are satisfied together. Then it prints the answer as a list of `name==version` lines. The flags used here:

- `--universal`: solve for every operating system and Python version at once; lines that apply only to some get a marker after `;`.
- `--extra dev`: also include the `[project.optional-dependencies] dev` group.
- `--generate-hashes`: add the SHA-256 hashes of every downloadable file of each version.
- `--python-version 3.12`: solve for Python 3.12 as the lowest version.
- `-o file`: write the result to a file.

The first lines of the output record the exact command, so anyone can regenerate the lock.

## Walkthrough of this repository's use

`requirements.lock`, lines 1 to 2:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock
```
`requirements-dev.lock`, lines 1 to 2:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --universal --extra dev --generate-hashes --python-version 3.12 -o requirements-dev.lock
```

Reading the two commands side by side:

- Both read `pyproject.toml`.
- The first has no `--extra`, so it holds only `[project] dependencies` (`psycopg[binary]`) and what those need.
- The second adds `--extra dev`, so it also holds `pytest`, `pytest-cov`, `ruff`, `mypy`, `import-linter`, `pip-audit` and everything they need.
- Both use `--universal --generate-hashes --python-version 3.12`.
- `-o` writes the file named at the end.

To refresh the locks (for example to take a newer ruff), run those two commands again from the repository root, review `git diff requirements*.lock`, and run `make check` before committing.

## Try it yourself

1. `uv --version` prints the version (`uv 0.11.2` when this repository was prepared).
2. `head -2 requirements.lock` prints the command that made the file.
3. In a scratch copy of the repository, run `uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o /tmp/lock-check.txt` and compare with `diff /tmp/lock-check.txt requirements.lock`; any difference is a newer release that was published since. This needs internet access.

## Mistakes people make

- Editing a lock file by hand.
- Regenerating the lock without checking what changed (every package version may move).
- Forgetting to regenerate it after changing `pyproject.toml`: the lock and the project then disagree.
- Assuming uv is needed on the machine that only installs from the lock; plain `pip` is enough.

**How this repository avoids them.** The command is recorded in the file, `make install` installs only from the lock, the lock is checked by `make audit`, and `git diff` shows exactly what a refresh changed.

## Check yourself

1. What does `uv pip compile` produce? *A pinned list of every package and exact version that satisfies the ranges, optionally with hashes.*
2. What does `--universal` change? *The result is valid on all platforms; platform-specific lines get markers.*
3. Which file is the input and which is the output? *`pyproject.toml` is the input; `requirements.lock` or `requirements-dev.lock` is the output.*
4. Why is the command written at the top of the lock file? *So anyone can run it again and get the same file.*
5. Does installing from the lock need uv? *No; it is a plain pip install with `--require-hashes`.*
